# Treasury & factor analysis tab — design

**Date:** 2026-07-29
**Status:** approved, ready for implementation plan
**Location note:** specs live in `specs/`, not `docs/` — `.gitignore` excludes `docs/` as personal/employer material
**Reference:** Quant Guild Library, *2026 Video Lectures / 130. Projects to Help you Become a Quant (Beginner) / 01 - Quant Trader / 01 - Intro - Trading Dashboard*, commit `043532e79`

## Purpose

Add a fifth analytical view to the AI DOF Command Centre: a quant tearsheet for Meridian
Holdings Group's treasury portfolio, plus a factor model of the group's own operating
revenue.

Two reasons it belongs here. First, treasury oversight is real Director-of-Finance work —
a holdco parks excess cash in marketable securities and someone must report its
performance, its risk, and its compliance with the investment policy. Second, it extends
the project's demonstrated range from FP&A into quantitative finance without bolting on an
unrelated second project: the portfolio belongs to Meridian, the operating factor model
regresses Meridian's own revenue, and both reconcile to the existing ledger.

The tab follows the same discipline as the rest of the project. The analysis is
reproducible and the data is synthetic and labelled as such, but the *findings are
planted* — the page's job is not to display statistics, it is to catch three policy
breaches that the headline statistics hide.

## Scope

In scope:

- Deterministic synthetic data generator, output committed to the repo.
- A pure-Python analytics module: performance/risk statistics, CAPM, Fama-French 3- and
  5-factor regressions, rolling factor betas, rolling Sharpe, treasury policy checks, and
  an operating factor model.
- A self-contained dark HTML tearsheet, ported from the reference project's templates and
  stylesheet, embedded in a new Streamlit page.
- Tests asserting the regressions recover the parameters baked into the generator.

Out of scope (deliberately deferred):

- **Visitor upload flow.** A later phase will let a visitor download a sample file from a
  landing page and upload it to see the dashboard render. This design does not build it,
  but `load_returns()` accepts a file-like object precisely so that phase is a wrapper,
  not a rewrite.
- Live market data. No brokerage or price feed integration.
- Any change to the four existing pages.

## Architecture

Three layers, strictly separated so the math is testable and reusable independently of the
presentation.

```
treasury/
├── __init__.py
├── analytics.py              parsing, statistics, regressions, policy checks
├── charts.py                 Plotly figure builders → HTML fragments
├── render.py                 Jinja2 → one self-contained HTML string
├── templates/
│   ├── base.html             ported: topbar, .bg-grid backdrop, footer
│   └── tearsheet.html        ported dashboard.html + section 2
└── static/css/style.css      ported, rebranded
generate_treasury_data.py     deterministic generator (run once, output committed)
data_compact/treasury/
├── ff_factors_daily.csv
├── treasury_portfolio_returns.csv
└── operating_factors_monthly.csv
tests/test_treasury_analytics.py
```

| Layer | Responsibility | May import |
|---|---|---|
| `analytics.py` | All math. CSV or buffer in, DataFrames and dataclasses out. | pandas, numpy, statsmodels |
| `charts.py` | Plotly figures as HTML fragments. No math beyond formatting. | plotly, `analytics` |
| `render.py` | Fill the Jinja2 templates, inline the CSS and Plotly JS, return one HTML string. | jinja2, `charts`, `analytics` |
| `streamlit_app.py` | Sidebar entry, window control, `components.html()` embed. | `render` |

`analytics.py` must not import Streamlit, Jinja2 or Plotly. `render.py` must not compute
statistics.

### Why a rendered HTML page rather than native Streamlit widgets

The reference project's look comes from a 332-line stylesheet built around a dark
`#0a0e17` background, translucent panels and a grid backdrop. Reproducing that inside
Streamlit means fighting Streamlit's own stylesheet with brittle, version-dependent CSS
injection.

Rendering the reference's templates and embedding the result via `components.html()`
avoids that entirely, and it is a pattern the repo already uses — the Details page embeds
`cfo-review-ai-dof-command-centre-jul2026.html` the same way. It also means `render.py`
can write the page to disk as `treasury-tearsheet-jul2026.html`: a committable portfolio
artifact that opens offline, in email and in print, exactly like the CFO review beside it.

The other four pages stay light. The tearsheet reads as its own terminal, which is what it
is.

## Data

All three files are generated by `generate_treasury_data.py` under a fixed seed, committed
to the repo, and labelled MODELLED in the README and on the page itself.

### `ff_factors_daily.csv`

Columns `date, Mkt-RF, SMB, HML, RMW, CMA, RF`. 522 business days, 2024-07-01 → 2026-06-30.
`RF` is a constant 4.3%/yr expressed daily. The four style factors are drawn as correlated
noise with small positive premia.

This panel is generated **first**, and both the benchmark and the portfolio are then built
from it: `SPY = Mkt-RF + RF`. Without that ordering the Fama-French loadings would be
regressions of one unrelated random series on another, and every number in the factor
tables would be noise. Building the portfolio from the panel is what makes the loadings
recoverable and the tests meaningful.

### `treasury_portfolio_returns.csv`

Columns `date, portfolio_return, SPY` — the reference project's exact schema, so the two
files are interchangeable.

| Property | Reference sample | This file |
|---|---|---|
| Index | business days, holidays included, no weekends | `pd.bdate_range` — same |
| Format | plain decimals, 6 dp, scientific for very small values | `round(6)` — same |
| SPY daily sd | ≈0.0098 (≈15.6%/yr) | 16%/yr by construction |
| Portfolio daily sd | ≈0.0113 (≈18%/yr) | ≈14.9%/yr FY2025, ≈23.7%/yr FY2026 — systematic and idiosyncratic components combined, derived from the loadings below rather than set directly |
| Rows | ~730 (2023-01-03 → 2025-11-25) | 522 (2024-07-01 → 2026-06-30, aligned to the ledger) |

Two regimes, which is where the planted findings live:

| | FY2025 (Jul-24 → Dec-25) | FY2026 (Jan-26 → Jun-26) |
|---|---|---|
| Mkt-RF beta | 0.85 | 1.31 |
| SMB | −0.15 | +0.55 |
| HML | +0.20 | −0.30 |
| Idiosyncratic vol | 6%/yr | 11%/yr |

A defensive, mildly value-tilted portfolio quietly rotates into high-beta small-cap growth
in the second half. Additionally: a six-week shock in 2026-Q1 sizing maximum drawdown past
the 10% policy limit, and a 45bp/yr fee drag netted out of the committed series.

**The alpha finding.** True alpha baked into the generator is small — +0.25%/yr in FY2025,
−0.50%/yr in FY2026 — while the SMB, HML and RMW tilts earn real factor premia present in
the panel. CAPM, having only a market factor, misattributes those premia to skill and
reports an alpha of roughly +2%/yr. The FF5 regression, which controls for them, reports an
alpha near zero; net of the 45bp fee it is negative. The finding is therefore not "alpha
fell" but "there was never any alpha — it was factor exposure, and the fee is being paid for
it." A 45bp fee could not arithmetically flip a genuine +2% alpha negative, which is why
the effect has to come from factor attribution rather than fee drag.

Committed returns are **net** of fees, matching how a custodian statement reads. Gross
figures shown on the page are derived by adding the fee back.

The full-period beta lands at ≈0.94 — inside the policy limit. **Only the 63-day rolling
window exposes the breach.** That asymmetry is the point of the page: the annual number
passes, the rolling number does not, and a Director of Finance who reports only the annual
number misses a live policy violation.

### `operating_factors_monthly.csv`

Columns `month`, per-entity revenue growth (`MHG, MLG, CFS, NWC, APX`), group revenue
growth, and three factors: `freight_rate_index, diesel_price, industrial_production`.
60 months, Jul-2021 → Jun-2026.

The final 24 months are **actual** monthly revenue, read from `Invoices.csv`, which carries
a monthly `Period` column (2024-07 → 2026-06) and an `Entity` column. No modelling is
involved in that half of the series. The first 36 months are synthetic pre-history, needed
because 24 observations cannot support a three-factor regression while 60 can.

Per-entity coverage is MLG, CFS, NWC and APX. MHG is the holding company and books no
invoice revenue, so it carries no loading.

A test asserts the last 24 monthly values equal the ledger's monthly revenue exactly.

## The analytics module

```python
# parsing — accepts a path, a file-like object, or raw CSV text
load_returns(source) -> DataFrame            # DatetimeIndex, cols portfolio_return, SPY
load_factors(try_live=True) -> (DataFrame, FactorSource)

# performance and risk
wealth_index(returns) -> Series
drawdown_series(returns) -> Series
perf_stats(returns, rf) -> PerfStats         # total return, CAGR, vol, Sharpe, Sortino,
                                             # max drawdown, hit rate, best/worst day
rolling_sharpe(returns, window) -> Series

# regressions
capm(port, bench, rf) -> Regression          # alpha (annualized), beta, R², t, p
factor_model(port, factors, k=5) -> Regression
rolling_factor_betas(port, factors, window) -> DataFrame

# judgment
policy_check(perf, capm_res, rolling) -> list[Breach]

# section 2
operating_factor_model(monthly) -> (Regression, DataFrame)   # group, then per-entity
```

`Regression` carries a list of `Loading(name, coef, annualized, tstat, pvalue,
significant, description)` — the exact shape the reference's factor tables render, so the
ported templates need no reshaping.

Column matching in `load_returns` is liberal and case-insensitive, following the reference:
date as any of `date|dates|datetime|timestamp|day`, portfolio as
`portfolio_return|portfolio|returns|strategy|…`, benchmark as
`SPY|spy_return|benchmark|market|mkt`. This is what makes the deferred upload flow cheap.

### Factor source

The app tries a live Ken French fetch first, and falls back to the committed panel on any
exception. The reference does the same, and reports which source it used via a banner. Ours
keeps that banner and is honest in it: when the committed MODELLED panel is used — which
will be the normal case — the warning fires and says the loadings are illustrative.

### Treasury policy

Three checks, stated as an investment policy on the page so the breaches are legible:

| Check | Limit | Result | Cash sizing |
|---|---|---|---|
| Peak rolling market beta | ≤ 1.00 | ≈1.3 — **breach** | excess beta × 20% market decline × notional |
| Maximum drawdown | ≤ 10% | past limit — **breach** | (realized MDD − 10%) × notional |
| FF5 alpha, net of fees | ≥ 0 | negative — **breach** | annual fee paid × notional |

Portfolio notional is a MODELLED constant, $9.0M of the group's cash — set in the generator
config and used only for sizing the breaches in dollars.

Figures above are targets, not assertions. The generator is tuned once against acceptance
bands (see the plan's calibration step) and the tests assert the bands, not decimal-exact
values — a test pinned to −14.2% would break on any harmless generator change.

Every check is computable from the two committed return series alone. An earlier draft
included a holdings-concentration limit; it is dropped, because the portfolio is stored as a
single return series with no sleeve-level weights, and a check the data cannot support has
no business on the page.

Each breach renders with the three things the `ai-dof` skill requires of a finding: why it
matters sized in cash, the risk it creates, and the action with an owner and a date.

## Page layout

The tearsheet mirrors the reference's `dashboard.html` element for element.

| Reference element | Here |

| `panel-wide` equity | portfolio vs SPY, growth of $1 |

| `benchmark-panel` | SPY CAGR / vol / Sharpe / max drawdown |

Palette is the reference's, verbatim: `--bg:#0a0e17`, `--panel:rgba(20,27,45,.72)`, accents
`#4ade80` and `#60a5fa`, `--danger:#f87171`, `--warn:#fbbf24`. Branding in the topbar
changes to `◆ AI DOF · TREASURY`.

### No CDN

The reference loads `plotly-2.35.2.min.js` and Google Fonts from the network. This repo is
offline-first — the CFO review dashboard has no external dependency by design — so Plotly
is inlined once and the page uses system font stacks. That costs roughly 3.5 MB of file
size and buys a page that renders on a plane, in an email client, and in print.

## Error handling

- Missing data file → a clear message naming the generator command, not a traceback.
- Live factor fetch → wrapped; any exception falls back to the committed panel silently and
  the banner reports the source.
- Fewer observations than the rolling window → suppress that chart with a note rather than
  emit a misleading empty or near-empty series.
- `load_returns` on a bad file → the reference's explicit errors, kept: empty CSV, missing
  column (naming the aliases it looked for), fewer than 30 valid rows, and a warning when
  values look like percentages rather than decimals.

## Testing

`tests/test_treasury_analytics.py`:

1. **Parameter recovery.** CAPM on the FY2025 slice recovers beta ≈0.85; on the FY2026
   slice ≈1.31; full period ≈0.94. FF5 loadings land within tolerance of the baked-in
   values in both regimes.
2. **Policy checks fire.** `policy_check` returns exactly the three intended breaches — a
   test that the planted findings are actually plantable, and stay planted if the generator
   changes.
3. **Ledger reconciliation.** Monthly operating revenue re-aggregates to the eight ledger
   quarters exactly.
4. **Loader robustness.** A synthetic replica of the reference CSV's schema and quirks —
   holiday rows, 6 dp decimals, scientific notation for tiny values, aliased column names —
   parses correctly.
5. **Statistics sanity.** Sharpe, Sortino and max drawdown against hand-computed values on
   a short fixed series.

The reference project's own `sample_portfolio_returns.csv` is **not** vendored into this
repo — that folder carries no license. It can be dropped in locally to spot-check
interchangeability; it is not committed and no test depends on it.
